# Чек-лист развёртывания

Подходит для локального запуска и для внешнего сервера, на котором жюри работает с прототипом. Порядок выкатки новой версии и отката — в [OPERATIONS.md](OPERATIONS.md).

## 1. Перед развёртыванием

- [ ] Выбран тег версии: `git checkout vX.Y.Z`, рабочее дерево чистое (`git status`).
- [ ] На сервере установлены Docker и Docker Compose v2. Go и Node.js на хосте не нужны.
- [ ] Свободны порты `3000` (web), `8080` (API) и `5433` (PostgreSQL). Все три публикуются только на `127.0.0.1`.
- [ ] Есть резервная копия БД, если это обновление существующей установки (см. [OPERATIONS.md](OPERATIONS.md#откат-версии)).

## 2. Конфигурация `.env`

```bash
cp .env.example .env
```

- [ ] `JWT_SECRET` — случайная строка не короче 32 символов: `openssl rand -base64 48`.
- [ ] `POSTGRES_PASSWORD` — на внешнем сервере обязательно не `alfa`.
- [ ] `LLM_BASE_URL` и `LLM_API_KEY` — шлюз и ключ организаторов. Без ключа работают лента и предварительное ранжирование, но не анализ.
- [ ] `LLM_MODEL_FAST`, `LLM_MODEL_REASONING`, `LLM_MODEL_WRITER` — только модели из списка кейса. Проверка: `docker compose run --rm api llmcheck`.
- [ ] Лимиты расхода соответствуют дневному бюджету ключа: `LLM_DAILY_TOKEN_BUDGET`, `LLM_DAILY_CALL_LIMIT`, `LLM_PER_MINUTE_LIMIT`, `ANALYZE_PER_USER_HOURLY`, `ANALYSIS_QUESTIONS_PER_ANALYSIS`, `ANALYSIS_QUESTIONS_PER_USER_DAILY`.
- [ ] Для внешнего сервера с доменом: `COOKIE_SECURE=true`, `ALLOWED_ORIGINS=https://<домен>`.
- [ ] `.env` не добавлен в git: `git check-ignore .env` печатает `.env`.

## 3. Данные кейса

- [ ] CSV организаторов лежат в `data/raw/` (`df_Uid_data_hack.csv`, `df_Uid_payment_hack.csv`, `df_Fid_Uid_link_hack.csv`); каталог игнорируется git.
- [ ] Тексты аналитики Альфа-Банка лежат в `data/research/` (в репозитории).

## 4. Запуск

```bash
docker compose up -d --build
docker compose ps                                   # db и api — healthy, web — running
docker compose --profile import run --rm importer   # CSV, аналитика банка, один опрос RSS; LLM не вызывается
```

- [ ] `curl -fsS http://localhost:8080/api/health` возвращает `{"status":"ok"}`.
- [ ] `docker compose run --rm api migrate status` — все миграции применены.
- [ ] В логах API нет ошибок: `docker compose logs api | grep -i error`.
- [ ] В логах есть строка `starting` с нужными моделями и `llm_configured=true`.

## 5. Публикация во внешнюю сеть

Compose публикует сервисы только на `127.0.0.1`, поэтому наружу их открывает reverse proxy с HTTPS (Caddy, nginx, Traefik). Пример для Caddy:

```text
alfainsight.example.ru {
    reverse_proxy 127.0.0.1:3000
}
```

- [ ] Наружу открыт только web через HTTPS. API и PostgreSQL снаружи недоступны: браузер обращается к API через same-origin `/api/*`, который проксирует Next.js.
- [ ] Включён `COOKIE_SECURE=true`, `ALLOWED_ORIGINS` совпадает с доменом.
- [ ] Проверено, что `https://<домен>/api/health` отвечает через прокси Next.js.

## 6. Smoke-проверка после развёртывания

- [ ] Регистрация и вход работают, после выхода `/api/me` возвращает 401.
- [ ] Онбординг: роль, интересы, компания из набора кейса.
- [ ] Лента открывается, сортируется по релевантности, у новостей есть предварительная оценка.
- [ ] Глубокий анализ новости выполняется. У анализа есть строка точности (покрытие источниками и проверка чисел), блок «Через какие признаки компании», действия с объектом, ответственным и сроком, источники.
- [ ] Блок «Как получен вывод» раскрывается: план, источники, самопроверка, шаги.
- [ ] Вопрос «Какие признаки компании использованы?» отвечается без модели, свой вопрос — моделью; повтор приходит из кэша.
- [ ] `/analytics/quality` показывает запуск, вопросы и метрики точности.
- [ ] Расход за проверку виден в `/api/system/status`, бюджет не исчерпан.

## 7. После развёртывания

- [ ] Настроено резервное копирование БД (например, ежедневный `pg_dump` по cron).
- [ ] Записаны тег версии, номер последней миграции и модели — понадобятся для отката.
- [ ] В течение суток просмотрены `/analytics/quality` и логи API: ошибки JSON, обрезанные ответы, ответы 429 от шлюза.
- [ ] Порядок отката понятен и проверен на копии: [OPERATIONS.md](OPERATIONS.md#откат-версии).
